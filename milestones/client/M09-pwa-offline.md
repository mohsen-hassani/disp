`<link rel="apple-touch-icon" href="/icons/apple-touch-icon.png">` and

## §17.3 Install prompt

- Capture `beforeinstallprompt`, `preventDefault()`, store the event.
- Show a dismissible install card on the dashboard (M05's territory for placement, this milestone
  owns the card's own logic) only when: the event was captured, the app isn't already in standalone
  mode, and `disp.installDismissedAt` (renamed from `mystuff.installDismissedAt` — M03 already
  reserved this key in its permitted-`localStorage`-keys table) is absent or older than 30 days.
- Dismissal writes the timestamp. Never a modal, never blocks content.
- iOS fires no `beforeinstallprompt` event at all — on iOS Safari (not standalone), show a one-line
  hint ("Share → Add to Home Screen"), same 30-day dismissal rule, same storage key.

## §17.4 Update flow

`registerType: 'prompt'`. A waiting service worker → non-blocking toast, "A new version is
available." with a Reload action calling `updateSW(true)`.

**The app MUST NOT auto-reload** — doing so mid-edit destroys unsaved input (a note being edited, a
settings form with dirty fields). If the user has unsaved changes anywhere the app can detect (M10's
form-dirty-tracking, M08's note editor), the toast persists until they act rather than forcing a
reload underneath them.

## §18.1 Scope — read-only offline, no write queue

Cached data is viewable; mutations require a connection. **No background sync, no offline mutation
queue.** This is a deliberate boundary, not a v1 shortcut to fill in later: an offline mutation queue
for a multi-user shared-resource app (two people editing the same shared note while one is offline)
raises conflict-resolution questions this spec does not answer, and a half-implemented queue loses
data. Do not build one "to be safe."

## §18.2 Runtime caching rules

| Route pattern | Strategy | Expiry | Notes |
|---|---|---|---|
| App shell (JS/CSS/HTML/icons) | Precache | — | Revisioned by build hash |
| `/api/auth/**` | **NetworkOnly** | — | Never cached, ever |
| `/api/dashboard/manifest` | StaleWhileRevalidate | 24h, 1 entry | |
| `/api/dashboard/tiles*` | NetworkFirst, 3s timeout | 1h, 20 entries | |
| `/api/notes` (GET) | NetworkFirst, 3s timeout | 24h, 30 entries | |
| `/api/notes/*` (GET) | NetworkFirst, 3s timeout | 24h, 50 entries | |
| `/api/settings/*` | NetworkFirst, 3s timeout | 1h, 10 entries | |
| Any non-GET `/api/**` | **NetworkOnly** | — | Never cached |

Only `200` responses are cached. Navigation requests fall back to the precached `index.html`,
**excluding** any URL beginning with `/api` (an offline navigation to `/api/whatever` must not
silently return the app shell).

## §18.3 Cache and credentials

Cached API responses contain the user's data, so:

- Every logout path (M03's soft/explicit/hard logout, §8.6) purges all Cache Storage entries whose
  URL contains `/api/`. **This milestone is what makes that purge meaningful** — M03 calls the purge
  today (or stubs it), this milestone defines exactly what's in the cache to purge.
- The service worker MUST NOT cache any response to a request bearing an `Authorization` header
  **other than** the GETs in the table above. Non-GET methods are never cached under any
  circumstance, full stop.
- The cache name MUST include the app version (`__APP_VERSION__` from M01) so a deploy invalidates
  stale API caches automatically.

## §18.4 Degraded authenticated mode

If bootstrap refresh (M03 §8.3 step 6) fails purely because the device is offline
(`navigator.onLine === false` and the failure is a transport error, not a `401`), the app **may**
render authenticated routes read-only using cached data, offline banner shown, every mutating
control disabled. It **must not** do this when the server actively rejected the refresh (expired/
revoked session must sign the user out) — this distinction is the entire reason M03's bootstrap
sequence branches on network failure vs. `401` separately rather than treating every refresh failure
the same way.

## §18.5 Offline UX

- `OfflineBanner` at the top of the shell whenever `navigator.onLine` is false, using `online`/
  `offline` events plus a periodic lightweight `HEAD /health/live` check every 30s while offline
  (browsers report `onLine` optimistically — confirmed the backend's `/health/live` route exists
  and does no DB access, per the earlier backend audit, so it's cheap to poll).
- All mutating controls disabled while offline, tooltip "You're offline."
- Data rendered from cache while offline gets a subtle "Showing saved data" line in each affected
  view (M05's tiles, M08's notes list/detail, M06's settings — this milestone provides the shared
  label component, each screen milestone wires it in based on whether its data came from cache).
- On reconnect, TanStack Query's `refetchOnReconnect` (M04's query client defaults) refreshes
  everything; the banner disappears with no reload.

## Open questions / judgment calls for the implementer

- The spec doesn't say whether the `HEAD /health/live` poll should back off if the tab is hidden —
  reasonable to pause it on `visibilitychange` to hidden (same pattern M03 already uses for
  proactive refresh) even though the spec doesn't say so explicitly, since polling an invisible tab
  every 30s serves no purpose and drains battery on mobile.
